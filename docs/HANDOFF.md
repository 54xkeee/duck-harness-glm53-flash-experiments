# 完整交接：Duck Harness × GLM-5.3-Flash

截至 2026-09-04。此文独立于本机路径和原对话，供另一个 ChatGPT 对话阅读。仓库内的报告、配置、事件、请求统计和代码可供进一步核对。API 密钥不在资料中。

## 1. 研究目标

我们希望模型通过「当前观察 → 机制假设 → 有区分力的动作 → 动作前预测 → 真实下一状态 → 支持或反例 → 修订与规划」逐渐建立可用的游戏理解。

重点不是让模型多写规则，而是让规则能接受现实检查，能支撑行动，失效时能撤回。最终目标是有限真实动作、模型调用和时间下完成更多关卡，而不是制造更多日志。

原 Duck 的价值：统一 Python 工具面，结构化观察，同色组件分割、邻接和局部裁剪，真实前后帧转移、历史与结果元数据，以及在规则确定后使用程序搜索和批处理。薄弱处是模型同时提出假设、解释证据、判断自己是否理解并放行动作，提示词中的方法论缺少独立执行约束。

## 2. 起点：用户提供的旧归档分析

这部分属于背景材料，不与本次新增 16 局混合统计。

- 旧 2×2 消融的四组各 2 次，首关成功全部是 1/2，首关成功率的 Probe/Ledger 主效应与交互均为 0。
- 旧 Ledger 在 4 个开启槽位中，没有一次在后续真实行动前发挥有效摄取：未调用或最后动作后才调用。它测试的是可选工具的实际缺席，不是有效记忆的负结果。
- 旧 Probe 主要检查模型的确认字段非空。一局将白色「+」错误自认证为可控体，120 动作中 110 次无影响。
- 另一局有 123 条 probe 记录、292 个模型回合，19 动作过首关但仍停留在第二关，提示单步保护也可能仪式化。
- Pi 一次混合 low/high 运行用了 77 步过首关；同 session 的 high warm retry 用了 13 步。后者继承知识，不是冷启动公平对照。
- 旧归档有端到端超时和工具错误问题，其有效性与当前仓库状态应分开。

这些背景促成两个优先改变：由主程序依据真实转移检查证据；自动把事实送入后续请求，而不是等待模型写笔记。

## 3. 评分修正

LS20 版本 `ls20-9607627b`，共 7 关，人类动作基线 `[22,123,73,84,96,192,186]`，权重 1..7，总权重 28。

本轮核对采用的计分：

```text
s_i = completed_i ? min(1.15, (human_actions_i / agent_actions_i)^2) : 0
game_score = 100 * min(sum(i*s_i), sum(i*completed_i)) / 28
```

只过首关最高为 100/28 = 3.571429。因此 13、19、21、22 步首关均达到相同完成度上限。原附件重算得到 19 步 4.107143、21 步 3.919663，遗漏了整局完成权重上限，后续已纠正。

真实 RESET 和重玩成本保留，完成关卡按全局高水位；首次过关动作数与整局累计投入分列，不挑最好一段。

## 4. 历史「3 点多分」基准

2026-09-02 有一次有效正式运行：GLM-5.3-Flash + Duck，21 个动作完成 1/7 关，得分 3.5714；首关约 1421.7 秒（23m42s）完成，实际运行约 35 分钟，第二关没有动作，最终预算结束取消。

有效动作在批处理中非常快：7 步约 3 秒，13 步约 4.9 秒。第 8 到第 9 步之间一个分析/工具阶段约 970 秒；这不是一条 HTTP 请求。过关后还有长时间无行动。

历史的生成 token 有两个不同口径：benchmark 逐动作合计 28,629，solver_note 为 50,082；不与新全请求 input/output usage 直接比较。

结论：这套配置有过高动作效率成功案例，但 3.5714 是单次结果，不是稳定均值。主要瓶颈之一是推理和调度未转化为更多关卡。

## 5. 第一轮：自动事实 × 位移验证门控

没有一次实现全部九阶段状态机、持久工具库和世界模拟器；先检验两个变量。

### 实现

**Verified Probe**：主程序根据真实前后帧匹配形状、位移和共同移动组件。两个不同前置棋盘支持相同位移后，才放行相应批处理。未知动作先一步；静止、预期偏离、终态截停余下批次及同一 Python 片段后续动作。

这只是重复位移证据，不是玩家身份、碰撞和目标规则的完整证明。

**Belief Store**：每个真实动作自动生成 evidence ID、事实、支持、反例和作用域；每次模型请求刷新主机摘要。区别于可选 Ledger，它实际进入后续上下文。level/reset/终态使当前动作模型失效，历史事实保留标签。

### 协议

baseline/probe/belief/combined 各 2 次；combined = probe + belief。每局新进程、新游戏、新上下文，不注入成功路线；GLM-5.3-Flash 智谱标准接口，thinking enabled、effort low、输出 8192、分析预算 90 秒；120 动作上限；完整进程 1800 秒；区组内随机顺序，最多 2 并发；全部失败保留。

### 结果

北京时间 10:15:24–11:31:34，约 76m10s。

| 组 | 首关成功 | 首关动作（失败标总动作） | 平均分 /100 |
|---|---:|---|---:|
| baseline | 1/2 | 43；失败120 | 0.4674 |
| probe | 0/2 | 失败118；失败22 | 0 |
| belief | 2/2 | 89；18 | 1.8948 |
| combined | 2/2 | 34；31 | 1.6470 |

全部最多 1/7，全游戏成功 0/8；695 真实动作。belief 的 18 步局后来重置，首关累计投入 22。

282 次请求实际注入事实，175 次真实 probe 介入。带 belief 两组均 2/2 首关成功，是值得保留的探索信号，不是稳定因果结论。probe 单独 0/2；一局还有 46 次连续无变化，说明停止同一批次不等于停止下一请求重复错误动作。

### 时间预算缺陷

外层 1800 秒得到遵守，但内层 1770 秒又被 TAAF 扣 600 秒，实际软预算只有 1170 秒（19.5 分钟）。最长进程 1187.024 秒。5 局 cancelled，3 局到 120 动作后 gave_up。没有在实验中途改预算；第二轮前统一修正。

40 项测试通过。第一轮是约 19.5 分钟有效窗口的探索结果，不是完整 30 分钟求解窗口。

## 6. 第二轮：动作前预测闭环

用户提出，希望用假设下的预测、行为和真实下一状态快速建立可修正的理解。

### 实现

每个动作可提交 `prediction`：rule_id、规则文本、当前格子条件、下一状态预期格子/关卡、规则依赖。

主程序先检查条件、复制预测、动作前落盘，再执行真实游戏。下一帧逐项核对。失配使规则版本 contested，依赖失活，停止余下批次及同一 Python 片段后续动作。修改规则文本产生新版本；没有把握时允许一次无预测探索后交回模型。符合预期的静止可以通过。

这里的「回退」是撤销知识采用和未执行计划，真实已执行动作仍然有效。没有任意状态恢复；RESET 是真实游戏动作。

当前组件核对具体状态预测，不验证规则文本全部语义，不是完整世界模拟器，也没有自动维护竞争假设或最优信息探测策略。

### API 与预检

文本检查 HTTP200、2.357s；图像+工具 HTTP200、2.811s，合计232 token。

第一次 combined pilot：158.691s，1 个无预测动作，5 请求/4响应/1超时，25,192 token；ARC 收尾另有评分核对超时。

第二次：216.117s，8 个无预测动作，22请求/19响应/3个429，270,059 token；2 个预测因坐标颜色前置条件错误被拒绝。正式前补充预期/实际颜色诊断，要求程序读取坐标而非猜色。pilot 不计入正式8局。

### 协议

| belief | 开 | 关 |

第二轮前106项测试通过。50份源码/helper/协议快照覆盖正式版本；八局期间无代码改动，结束后逐字节核对。是开发重复评估，不是比赛提交。

## 7. 预测实际覆盖与信息价值

四个预测槽位99动作中95个有有效动作前预测，61匹配、34失配，其中2个失配在过关边界。另有85次执行前拒绝、38次执行后停止。

累计检查172个格子；对应真实动作变化6036格，只覆盖108格，约1.79%。64.21%的整体匹配率不是完整世界状态准确率。

- 63次含预测变化格：30次匹配。
- 32次只预测静止格：31次匹配，包含背景/HUD。
- 显式规则依赖只提交1次，传递失活0次；功能测试通过，不代表在线收益已证实。

低像素覆盖也不自动等于无价值，因为像素可能冗余；真正缺少的是「这些检查是否足以区分候选机制并支持行动」的评价。

## 8. 案例：判断正确，反馈却丢失

r1-1 combined 约29分钟只执行14动作，22次执行前拒绝，107请求，未过首关。独立核对其47个格子检查及11个条件冲突坐标，未发现主程序取色或比较错误。

第一次LEFT因空expected未执行，但普通stdout使工具包装省略了结构化action_results。模型看见自己打印的「L False 52」，使用了之前RIGHT留下的转移，误以为LEFT真的发生。

所以问题是执行事实没有可靠送达模型：拒绝→原因漏显→旧状态冒充本次结果→错误理解继续传播。

同局动作4后35请求、316.797秒API时间，有9次拒绝其中8次沿用contested规则；动作11后28请求、783.287秒，仅1次拒绝，主要是重复看图和8次超时。不是全部停滞都由门控造成。全局请求等待1700.900秒，约占96.98%。

## 9. 案例：改名不等于修复

r1-4 prediction 第21动作过首关，约进程启动后19m10s，最终49动作。首关的8次匹配检查橙/蓝移动物体进入与离开格，不是纯HUD，但每步只核对2格，实际约52格变化。

上移规则从move_up改名到move_up_v2…move_up_v11，描述仍相同，各host version又从1开始。模型明确以换ID继续执行。这不能作为反例促成语义修复的证据。

规则ID版本系统只追踪模型声明的标识；尚无语义同一性判定。此局同样遇到stdout漏显，但主动查看last_action_result较快恢复诊断。

## 11. 是否退步？历史比较有哪些混杂

现象上，历史成功3.5714对比第二轮prediction/combined的[3.5714,0]，均值下降；最好成绩不变、成功未稳定复现。belief第一轮均分1.8948到第二轮0.1324也下降。

但历史只一次，新baseline不是历史配置的原样复现：

| 项目 | 历史 | 第二轮 |
|---|---|---|
| 路由 | OpenCode Zen Go | BigModel标准接口 |
| reasoning effort | 未记录，未知 | low |
| thinking显式设置 | 未记录；可见reasoning输出 | enabled |
| 输出上限 | server default，真实值未知 | 8192 |
| 实际输入预算 | 64512 | 56832 |
| analyzer timeout配置 | 300秒 | 90秒 |
| yield | 60秒 | disabled |
| 实际窗口 | 约35分钟 | 约29分钟 |
| 动作上限 | 60 | 1200 |
| 外层并发 | 1 | 2 |
| 源码冻结 | 历史缺完整快照 | 完整保存本轮选定快照 |

新baseline自己0/2。因此路由、公共配置、时长、源码、并发、随机性和新控制器影响尚未分离。旧300秒精确语义缺历史源码证据，不直接套用新共享轮次逻辑；也不要把旧effort猜成high/max。

本轮报告早期的「动作效率收益」偏积极，更准确是「出现高效率成功样本，尚未隔离稳定因果收益」。严格恢复历史配置有缺失项，只能明确标注未知并尽可能复原，而不是声称能完美复现。

## 12. 实验后的反馈修复

正式8局结束并确认冻结版本后，修改预测组工具输出：host_control总在stdout之前；明确本次真实执行数、停止原因、错误、rule_id/version、最多8项偏差；保留首次停止原因；只看图的调用执行数明确0；超长stdout裁剪但保留主机摘要；关闭预测保持原路径。

新增7项Python sandbox回归，覆盖stdout、超长输出、前置拒绝、实际失配、部分执行后拒绝、历史转移隔离和关闭功能。完整113项测试、Ruff通过。

版本边界：正式成绩属于修复前快照。当前修复版只完成功能验证，没有新的完整性能实验。规则改名和时间预算问题没有在该补丁中一并解决。

## 13. 已知与未知

已知：自动事实和预测确实送达真实行动链；检查器能核对具体预测；反馈链曾漏显；规则改名和低信息预测实际发生；预算参与制造短截止；全部16局最多第一关。

未知：预测是否稳定提升通关/得分；规则版本是否促进真正修复；依赖是否有在线收益；是否形成跨关理解；退步各因素贡献；反馈补丁是否恢复成绩。

「记录可核对」「局部预测命中」「机制理解」「规划有效」「比赛得分提高」是不同层次。

## 14. 希望后续对话思考的问题

1. 最小有效预测应是格子、对象、关系、资源还是阶段？如何避免只预测静态背景？
2. 如何管理少量竞争假设，选择区分度高且成本低的动作，而不是机械逐步记录？
3. 反例如何区分读图错误、漏条件、规则错误、新关卡和暂态，并真正改变后续预测？
4. 怎样保留Duck「想清楚后快速批处理」的优势，只在有价值的偏差处返回模型？
5. 如何先对齐公共配置，分别测试反馈补丁、预测、事实摘要和时间预算，避免一次改多项？
6. 怎样把指标重点从少数首关优胜样本转向第二关、跨关迁移和单位资源完成度？

总体判断：本轮把部分自述推理变成了可检查的执行过程，也发现了具体工程缺陷；尚未证明预测闭环使Duck稳定更强。下一步应减少无价值的动作和模型往返，让每次试验真正区分机制，让反例真正改变判断。
