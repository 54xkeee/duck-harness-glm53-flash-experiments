# Duck Harness 改进与 GLM-5.3-Flash 实验

日期：2026-09-04

## 1. 对附件方案的修订

保留 Duck 的 Python 单工具面、对象分割、真实转移和回放工件。本轮集中检验两个可执行处理变量，而不是一次引入完整状态机、持久代码库和世界模拟器。

| 附件中的方向 | 本轮落实方式 | 验收证据 |
|---|---|---|
| 用 verifier 代替模型自认证 | 主机从真实帧差分提取唯一形状匹配和共同位移；两个不同前置棋盘支持相同位移后，才放行该动作批处理 | `tests/test_evidence_controller.py` |
| 自动 belief store | 每个真实动作生成 evidence ID、事实、支持记录和反例；每次模型请求刷新系统消息中的主机摘要 | `tests/test_glm_evidence_io.py`；`artifacts/*usage.jsonl` |
| 事务式执行 | 未知动作只执行一步；静止、预期偏离和引擎终态切断批次；同一 Python 片段再次调用动作也受边界约束 | 主机 `probe_control.intervened` 事件和测试 |
| 多色对象 | 复用现有同色组件分割，按跨帧共同位移合并观测；竞争位移不升级 | 多色组件与竞争位移 fixture |
| 资源控制 | 四臂统一 `low`、8192 输出上限、90 秒决策窗口；整局外层进程组截止含收尾 | 请求 telemetry、进程截止测试 |
| 跨关记忆 | level/reset/终态使当前作用域动作模型失效；历史事实保留关卡标签 | 作用域失效测试 |
| 处理变量摄取 | Probe 统计真实中断，不把开关打开当处理生效；Ledger 统计带真实事实的模型请求 | 每局事件和 usage 工件 |

这里验证的是**重复观察到的一致位移**，不是已经证明某个对象就是玩家，也不是普适的因果验证器。HUD 形变可以与移动共存；重复形状、遮挡和多个竞争移动体会让控制器保守地维持单步。关卡特有的碰撞、资源和目标条件仍由模型分析。

两个开关独立：`DUCK_VERIFIED_PROBE` 控制执行；`DUCK_BELIEF_STORE` 控制自动事实注入。没有“提交几段文字即可解锁”的接口。Python 对返回对象的修改也不再重写主机动作记录。

### 本轮暂缓

完整九阶段状态机、通用数字网格查询库、持久审计工作台、动态 high/max 调度和主动世界模型分配，待这两个处理变量的结果支持后再做。固定推理强度是为了保持四臂可比，不把资源策略叠加成第三个变化因素。

## 2. GLM 接入修正

本轮使用智谱标准接口 `https://open.bigmodel.cn/api/paas/v4/`，模型 ID 为 `glm-5.3-flash`；与历史 `opencode-go` 路由分开记录。

该模型的 `thinking.type` 为 `enabled`；`reasoning_effort` 接受 `low/high/max`，默认 `max`。旧兼容层只对 vLLM 发 thinking 字段，本轮增加智谱请求字段，显式选择 `low`。这为历史长延迟提供一个待检验解释，而非把旧路由的行为直接归因于智谱默认值。[智谱模型文档](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash.md)

token 直接记录每个请求的 provider usage：输入、completion、reasoning 和缓存命中分别保留。completion 可能已包含 reasoning，不重复相加；缺失值为 null，失败请求的未知消耗不计为零。

密钥从进程环境传递，不写入实验配置或报告。后续调用继续使用同一模型 ID，而非切回历史模型路由。

## 3. 计分修正

附件提到每关效率上限从 1.0 调整为 1.15，但其重算遗漏了完成关卡权重比例对整局分数的上限。当前规则为：

```text
si = completed_i ? min(1.15, (human_actions_i / agent_actions_i)^2) : 0
game_score = 100 * min(sum(i * si) / sum(i), sum(completed i) / sum(i))
```

因此 LS20 共 7 关、只完成首关时，19 和 21 动作的整局分数均为 `100/28 = 3.571429`，不是 `4.107143` 或 `3.919663`。更高的单关效率可抵消其他已完成关卡的低效率，但整局仍受完成度上限约束。[官方计分方法](https://docs.arcprize.org/methodology)、[Toolkit 版本记录](https://docs.arcprize.org/toolkit/overview)

报告同时保留本地框架原始分数与按当前规则重算值；后者从实际游戏版本、基线动作和真实轨迹计算。固定公式文本与核对日期即可追溯，本轮不增加额外哈希系统。

- 游戏：LS20；每局 120 真实动作上限。
- 每局新进程、新模型上下文、新游戏 session；不注入历史成功路线。
- 每个重复区组内固定种子随机排列四臂，最多并行 2 局，两个区组分开执行。
- 1800 秒包含启动、游戏、退出和记录收尾；1770 秒开始终止仍在运行的子进程。
- 四臂共享模型、推理强度、输出上限、图像输入和请求截止。
- 主分析包含启动失败、零动作、provider 错误与超时。协议符合性和实际处理摄取另列。
- 当前实验属于本地开发评估；比赛模式另有单一 scorecard、每环境一次 make 和仅 level reset 等规则，八次开发重复不等于正式比赛提交。[比赛模式说明](https://docs.arcprize.org/toolkit/competition_mode)

样本量每臂 2 次，只支持仪器检查和探索性比较。报告会区分过关率、动作效率、请求耗时、错误率与处理摄取；单个优胜局不等于稳定提升。

## 6. 最终结果

八槽全部收尾。北京时间 10:15:24–11:31:34，端到端历时约 76 分 10 秒。

| 臂 | 首关成功 | 两次首关动作（失败局列已用动作） | 平均整局分 / 100 |
|---|---:|---|---:|
| baseline | 1/2 | 43；失败 120 | 0.4674 |
| probe | 0/2 | 失败 118；失败 22 | 0.0000 |
| belief | 2/2 | 89；18 | 1.8948 |
| combined | 2/2 | 34；31 | 1.6470 |

全部成功局仅完成 1/7 关，整场成功为 0/8。belief 第二局在首次过关后又发生重置，因此其整局首关累计投入是 22，首次过关是 18；两项口径在补充分析中分列。

### 结论与下一步取舍

1. **自动事实记录是本轮最值得保留的方向。** 两个带 belief 的臂均 2/2 过首关，而且处理真正送达模型：belief 单独臂 136 次、combined 臂 146 次，共 282 次有事实的请求。与附件中 Ledger 0/4 在线摄取不同，本轮确实测试了这个处理。
2. **单独 probe 门控没有获得支持。** 两次均未过关；其中一局仍出现 46 次连续画面无变化。单步中断只阻止同一批次扩散，尚未阻止模型在后续请求反复选择同一无效动作。
3. **组合臂更稳定地减少了这两局的首关动作，但还不是普适结论。** 34、31 动作均过首关；平均整局分仍低于 belief 单独臂，后者被 18 动作优胜局拉高。每臂只有两次，保持两个处理可切换，不据此固定全局默认策略。
4. **第二关仍是主要瓶颈。** 所有臂都止于最多一关。扩大硬编码状态机或持久代码库之前，应先处理跨关重建、无效动作重复与实际可用时间窗口。

### 时间预算实测

外层 1800 秒上限得到遵守，8/8 在时限内，最长 1187.024 秒。现有 TAAF InlineTarget 从 1770 秒内层预算再扣 `min(600, 1770/2)` 收尾缓冲，实际软预算是 **1170 秒（19.5 分钟）**；初始化还占用其中一部分。本轮保持这个规则一致，未在中途改动代码。

5 局因内层软预算结束而标记 `cancelled`，另外 3 局在 120 动作上限后标记 `gave_up`。进程正常退出不是游戏获胜。后续若检验完整 30 分钟游戏窗口，应先统一内外截止计算，再另开一轮，避免把预算变化混作控制器收益。
