# Duck Harness：先预测，再行动，再校验

日期：2026-09-04。正式实验 8/8 已完成。

## 结论先行

预测闭环已实现，并在真实游戏中产生可核对的动作前预测。**本轮呈现动作效率收益，但未证明稳定提升或跨关理解。** 事实记录组首关成功 2/2；预测组和组合组各 1/2，成功局分别以 21、13 个动作过首关，因此平均比赛分更高。八局均未通过第二关。

正式结果属于下面记录的冻结版本。实验结束后另修复工具反馈漏显，修复版的测试与版本边界单独列在文末，不把上述八局当成该补丁的通关证据。

## 本轮实现

原有 Duck 继续负责看图、Python 计算、机制假设和路线搜索。新组件只负责让其中的预测成为可检查的记录：

1. 模型在动作对象中提交 `prediction`，包括规则名称、规则描述、当前格子条件和下一步预期格子／关卡。
2. 主程序检查条件与规则依赖，把预测拷贝并记入动作前事件，再调用真实游戏。
3. 主程序根据下一帧逐项核对，记录命中、偏差和核对覆盖率。
4. 偏差使相关规则版本进入 contested 状态，依赖规则失活；停止当前批次及同一 Python 片段后续动作。
5. 修订规则描述生成新版本。新版本的成功预测单独计数，历史反例保留。
6. 没有把握时允许一个无预测的探索动作，然后把真实结果交回模型。预期静止本身不是错误。

规则文本由模型提出，主程序核验的是具体预测，并不解释文本中的全部语义。一次格子预测命中也不等于游戏机制已被证明。

### 预测接口

```python
action({
    "action": "RIGHT",
    "prediction": {
        "rule_id": "movement",
        "rule": "在当前已检查的通道条件下，对象向右移动一格",
        "conditions": [[3, 2, "g"], [3, 3, "W"]],
        "expected": {"cells": [[3, 2, "W"], [3, 3, "g"]]},
        "depends_on": []
    }
})
```

以上是接口示例，不是 LS20 路线。坐标从 0 开始，颜色字母取自当前工具棋盘。每个批次动作分别携带预测。

### 回退的含义

本轮回退针对规则使用权和动作计划：保留旧版本与反例，停用受影响的依赖，重新预测。真实游戏已执行的动作仍然生效；RESET 是游戏动作，并非任意状态快照恢复。

### 与上一轮的差异

| 上一轮 probe | 本轮 prediction |
|---|---|
| 根据已观察位移，事后判断是否异常 | 动作前提交具体预期，再比较真实结果 |
| 静止就截停 | 符合预期的静止可通过核对 |
| 动作级位移缓存 | 命名规则、版本、条件和显式依赖 |
| 主要数介入次数 | 同时记录预测命中、真实变化覆盖、反例后修订 |

旧 probe 在本轮四组中统一关闭。事实记录开关保留，作为独立对照因素。

## 实验设计

- LS20；baseline、belief、prediction、combined 四组，各 2 次，最多并行 2 局。
- 每局新进程、新游戏、新模型上下文；不输入上一轮成功路线。
- GLM-5.3-Flash，官方标准接口，统一 low、8192 输出上限及图像输入。
- 每局最多 1200 个真实动作；整个进程最多 1800 秒，包含启动与收尾。
- 修正上一轮内部预算多扣 600 秒的问题，并预留启动与收尾时间；实际有效时间另记。
- 四组内比较是本轮对照。与上一轮的时长、动作预算不同，旧结果仅作背景。
- 主结果为全部已分配试次的通关数、完成关卡、动作和重算分数；接口失败另列，保留在总体结果中。
- 预测指标分开列出动作覆盖率、核对命中率、变化格子覆盖率，以及反例后新版本的后续表现。只检查静态背景的命中不解释为世界模型准确。
- 每组 2 次用于探索性比较，不据此宣称稳定领先。

## 验收与结果

### 离线验收

最终冻结前 106 项测试通过，包含原有 40 项、预测控制器 34 项、预测集成 13 项、新实验运行与分析 19 项。相关修改文件 Ruff 通过。测试覆盖动作前落盘、预测拷贝隔离、前置条件和依赖拒绝、静止预测、同段后续动作截停、作用域切换、摘要压缩、故障熔断、暂停后的 pending 续跑以及进程组截止。

### 真实游戏预检

第一次 combined 预检：158.691 秒，1 个真实探索动作；5 次模型请求中 4 次响应、1 次 ReadTimeout，记录 25192 token。尚无可评分预测，因此只确认启动、探索动作、状态注入和事件链。游戏结束时另有一次 ARC 服务评分核对超时，日志与模型超时分开保留。

第二次 combined 预检：216.117 秒，8 个真实探索动作；22 次请求、19 次响应、3 次 HTTP 429，记录 270059 token。模型提交过 2 次预测，但格子前置条件均与真实颜色不符，被动作前拒绝；之后使用无预测单步。因此已确认模型尝试调用接口，但尚未观测到被评分的预测。该预检促成一个通用反馈修正：条件失败时显示预期／实际颜色，并在提示中要求程序读取坐标颜色、用探索得到的假设继续做具体预测，而不是猜坐标或反复省略预测。预检结果不混入正式分母。

正式实验于北京时间 18:18:48–20:15:24 运行，共约 116 分 36 秒。运行期间冻结 harness、运行器与分析器；八局结束后、后验修复前，50 份冻结源文件与运行工作区逐字节一致。

### 闭环实际做了什么

- 4 个预测相关试次共 99 个动作，其中 95 个带有效预提交预测，61 个匹配、34 个不匹配；2 个不匹配处于过关边界。
- 另有 85 次执行前拒绝，全部保留；38 次已执行动作触发停止，停止次数不等于节省动作数。
- 所有可评分预测累计检查 172 个格子。在相应真实动作的 6036 个变化格中，只覆盖 108 个，约 1.79%。全预测匹配率 64.21% 不是完整世界状态准确率。
- 含预测变化格的 63 次预测中，30 次匹配；只预测格子静止的 32 次中，31 次匹配。后者包含简单背景／HUD 检查，单列而不包装成复杂机制理解。
- 正式记录中仅 1 次提交了显式规则依赖，依赖传递失活触发为 0。此能力通过离线测试，但本轮尚未证明其在线收益。
- 模型有把旧规则改名后继续行动的行为；规则版本与“修订后匹配”仅是声明与局部观测，不等同于语义修复。

### API 与时间

正式轮共 925 次请求，843 次响应、82 次异常、0 次未收尾请求。异常为 80 次 ReadTimeout、1 次 HTTP 429、1 次 HTTP 500；无持续故障触发队列暂停。

这些超时并非全部代表服务持续失效：客户端按当轮剩余决策时间设置截止，80 次超时请求中有 28 次起始截止小于 10 秒、47 次小于 30 秒，中位数 20.916 秒，最短约 0.042 秒。模型延迟与本地时间分配共同影响失败次数。

已返回 usage 合计：输入 22,502,042 token，其中缓存输入 14,067,264；输出 281,235，其中推理 140,143；总计 22,783,277。推理已包含在输出中，失败请求的未知消耗未补零。这是观测用量，不是账户账单。

八个正式进程日志均未出现预检阶段那条 ARC reconciliation failed 警告。

### 已结束案例：r1-1-combined

该局在 1753.914 秒内执行 14 个动作，未过首关。12 次可评分预测中 5 次匹配、7 次不匹配，另有 2 次无预测探索；22 次动作前拒绝包括 12 次沿用 contested 规则、5 次空 expected、5 次前置条件错误。全部 47 项格子检查及 11 个被拒绝的条件冲突坐标，均可从记录画面独立复核，未发现主程序取色或判定错误。

该局暴露了一个反馈呈现问题：模型代码只打印普通 stdout 时，现有工具包装会省略结构化 action_results。第一次 LEFT 因空 expected 被拒绝，模型却只看到自己打印的 `L False 52`，把上一真实 RIGHT 的差分当成这次 LEFT 已执行。完整拒绝事件已落盘，但未在那次工具文本中强制呈现。逐字记录（原报告引用；见本仓库证据索引）

两段停滞应分开解释：动作 4 后，35 次请求用了 316.797 秒 API 时间，9 次拒绝中有 8 次沿用 contested 规则；动作 11 后，28 次请求用了 783.287 秒，其中仅 1 次拒绝，主要是重复读图及 8 次超时。后者不是主程序一直阻挡动作。

107 次请求共 93 次成功响应、14 次 ReadTimeout，调用耗时合计 1700.900 秒，占整局约 96.98%。首次匹配仅检查一个未变化的 HUD 格子，实际变化格覆盖为 0；全局可评分动作的变化格覆盖仅约 6.32%。匹配率与实际理解程度应分开看。

以上是已结束单局的机制诊断，不是八局总体结论；正式运行期间保持代码不变。

### 已结束案例：r1-4-prediction

该局第 21 步首次过关，约为进程开始后 19 分 10 秒，最终 49 步、完成 1 关。首关阶段 8 次预测匹配确实检查了橙色／蓝色移动物体的进入格和离开格，不是静态 HUD；但每步只核对 2 个格子，实际约有 52 个变化格子，仍属于局部验证。

上移规则并未表现出成功修复：模型从 `move_up` 改名为 `move_up_v2` 至 `move_up_v11`，规则描述仍相同，而各自的 host version 都是 1；逐字记录中明确说换 rule id 再执行。左右移动后续有匹配，上移预测持续失败，过关动作也因为换关画面而记为不匹配。这局支持“带局部预测也可过首关”，不支持“规则版本机制已促成稳定修复”。改名记录（原报告引用；见本仓库证据索引）

该局同样出现普通 stdout 省略拒绝原因，不过模型较快主动打印 `last_action_result` 查回诊断。版本与依赖只追踪模型声明的标识，尚无语义级规则同一性判定；换名行为在日志中保留，不算作旧规则修复。

## 实验后反馈修复与最终验收

八局全部结束并核对冻结源文件之后，才修改 `tool_agent.py` 的预测组返回逻辑：

- 无论模型是否打印 stdout，都将本次调用的 `host_control` 放在工具返回最前面。
- 明确实际执行数、停止原因、错误、规则 ID／版本，以及最多 8 项实际偏差。
- 同一片段的后续动作被拦下时，保留首次停止原因；部分批次已执行再拒绝，也分别报告。
- 只读本次主机动作结果；纯查看画面的调用明确执行数为 0，避免上一转移冒充新动作。
- 整条预测组结果按字符近似预算裁剪，主机摘要优先，超长 stdout 让出空间；关闭预测功能时保持原输出路径。

新增 7 项真实 Python sandbox 回归，覆盖普通／超长 stdout、前置拒绝、实际失配、部分执行后拒绝、历史转移隔离和关闭功能后的旧行为。最终完整套件 **113 项通过，Ruff 通过**；仅有原依赖的 14 条弃用警告。

**版本边界：** 正式 8 局统计对应修复前 `source_snapshot`。当前工作区含上述实验后反馈修复；该补丁通过功能回归，本轮没有再对其追加八局性能对照。通关与分数结论只归于冻结版本，保留全部成功和失败样本。
